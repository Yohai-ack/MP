CHECKBOUNCE: INSTRUCTIONS AND RESULTS SHEET
===========================================

Purpose
~~~~~~~
Find out which input on the cart shows contact bounce, so we can choose the
setup for Assignment 1, Part C (counting button presses: level, edge, and
debounced edge).

The program watches four inputs at the same time, with NO debouncing:
  1. The four I2C buttons on the IO board (read over I2C, as fast as possible)
  2. The blue Nucleo button B1, through its interrupt (EXTI)
  3. The blue Nucleo button B1, read in the main loop
  4. The IR obstacle sensor at the front of the cart

For every input it counts the edges, and it times the gap between consecutive
edges. A person cannot press twice within a few tens of milliseconds, so any
gap shorter than 30 ms (a "short gap") is bounce.

Nothing moves: the program never drives the wheels, the LEDs or the servo.
You do everything through Live Expressions. PuTTY is not needed.

Where you fill something in, it looks like this:  [ ______ ]
Write your value between the brackets.


PART 1: SETUP (once)
====================

1. Hardware
   - Cart with the IO board connected, as for the hardware test.
   - USB cable from the Nucleo to the PC.
   - Power jumper on the Nucleo: 5V_STLK.

2. Open the project in STM32CubeIDE
   - File > Import > General > Existing Projects into Workspace > Next.
   - Select root directory:
       C:\Users\yohai\git_codes\STM32\ass1\solution\checkBounce
   - Make sure "checkBounce" is ticked, and "Copy projects into workspace"
     is NOT ticked. Finish.
   - Do NOT open checkBounce.ioc and do NOT press Generate Code. The project
     is ready as it is.

3. Build and start debugging
   - Select the project, press the hammer (build). Expect 0 errors.
   - Press the bug icon (F11). If asked, choose "STM32 C/C++ Application",
     then OK. The debugger stops at the start of main().
   - Press Resume (F8). The program now runs.

4. Live Expressions
   - Window > Show View > Live Expressions (if it is not open already).
   - Click "Add new expression" and type each name below, exactly as written
     (one per line). Arrays (marked [4]) show a small arrow; open it to see
     elements [0] to [3].

     INPUTS (you will write these):
       resetCounts
       shortGapUs

     OUTPUTS (you will read these):
       loopsPerSec
       i2cOk
       i2cHeld
       i2cReadsPerSec
       i2cPresses          [4]
       i2cShortGaps        [4]
       i2cMinGapUs         [4]
       b1IrqRises
       b1IrqShortGaps
       b1IrqMinGapUs
       b1Level
       b1PollRises
       b1PollShortGaps
       b1PollMinGapUs
       irLevel
       irObstacles
       irShortGaps
       irMinGapUs

   - To write an input: click its Value cell, type the new number, press
     Enter.
   - "resetCounts": write 1 to set every count back to zero. The program sets
     it back to 0 by itself immediately.
   - "shortGapUs" is 30000 (30 ms). Leave it, unless I ask you to change it.

5. Meaning of the outputs
   - ...Presses / ...Rises / ...Obstacles : number of edges counted.
   - ...ShortGaps : number of edges that came less than 30 ms after the
                    previous edge of the same input. 0 = no bounce seen.
   - ...MinGapUs  : the shortest gap seen, in microseconds (1000 us = 1 ms).
                    4294967295 means "no gap measured yet".
   - i2cHeld      : bit n is 1 while I2C button n is held (1, 2, 4, 8).
   - b1Level      : 1 or 0, the current level of the B1 pin.
   - irLevel      : 1 = no obstacle, 0 = obstacle.

HOW I WILL READ THE RESULTS (for your information)
==================================================

  - Presses equal to 20 and ShortGaps = 0  ->  no bounce visible on that input.
  - Presses above 20 or ShortGaps above 0 ->  bounce, so that input can show
    the difference between plain edge counting and debounced counting.
  - MinGapUs of a few hundred to a few thousand us is typical bounce.
  - If the interrupt (Irq) shows bounce but polling does not, the bounce is
    shorter than one polling period.
