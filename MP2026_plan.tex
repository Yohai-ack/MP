\section{Assignments and quizzes}

\subsection{Assignment 1: ``No wheels''}

\textbf{Learning outcome.} Students will be introduced to C programming on real hardware. They will learn to select
appropriate variable types, predict and explain overflow and wrap-around, manipulate individual bits using shifts and
masks, use inputs (buttons and a sensor) to modify the program's behaviour, and produce timed LED behaviour on the
hardware, driven by the microcontroller. At this stage, we treat some internal communication paths (e.g., the I2C
bus) at a high level; we cover them later in the course.

\medskip\noindent
\textbf{Provided files:}
\begin{itemize}
\item \texttt{ass1.ioc}: the project configuration. It connects the hardware used in this assignment (LEDs, buttons,
      sensor) to the pins of the microcontroller and contains only what this assignment needs. Turn it into a
      CubeIDE project as shown in tutorial~1; you do not need to change it.
\item \texttt{io\_board.h} and \texttt{io\_board.c}: ready-made functions for the RGB LEDs and the push buttons of the
      IO board, which talk to the board over a communication bus called I2C. Copy \texttt{io\_board.h} to
      \texttt{Core/Inc} and \texttt{io\_board.c} to \texttt{Core/Src}, add \texttt{\#include "io\_board.h"} to
      \texttt{main.c}, and call \texttt{ioBoardInit()} once in the \texttt{USER CODE BEGIN 2} section.
\end{itemize}

\paragraph{One program for the whole assignment, chosen by \texttt{task}.}
All the tasks of this assignment are in one program. A global variable chooses what runs. Declare it in
\texttt{main.c}, in the \texttt{USER CODE BEGIN PV} section, exactly like this (same name, same type, global and not
\texttt{static}):
\begin{lstlisting}
volatile uint8_t task = 0;   /* the task that runs: change it in Live Expressions */
\end{lstlisting}
To choose a task, write its number into \texttt{task} in Live Expressions while the program runs. The tens digit is
the part, the units digit the item:

\smallskip\noindent
Rules for the program:
\begin{itemize}
  \item It starts idle (\texttt{task} = 0). When the variable \texttt{task} gets a new number, the program prints
        \texttt{=== task N ===} and runs task N.
  \item Every task checks \texttt{task} on every pass of its loop, and returns as soon as it changes. Before the next
        task starts, LD2 and all the RGB LEDs are switched off.
  \item A task that finishes by itself (not every task does: some run until the variable \texttt{task} changes) prints
        \texttt{=== task N done ===} and then waits until \texttt{task} changes. To run it again, write 0 and then
        its number again.
  \item A number that is not in the table prints \texttt{no task N}.
\end{itemize}
Start from this skeleton. Write one function per task, and add a \texttt{case} for each one:
\begin{lstlisting}
/* in the while (1) loop of main(), USER CODE BEGIN 3 */
uint8_t current = task;   /* a local copy for this pass (not a global, so not in PV) */
if (current != 0)
{
    printf("=== task %u ===\r\n", current);
}
switch (current)
{
    case 0:  while (task == 0) { }   break;   /* idle: wait for a choice */
    case 11: taskA1();               break;
    case 12: taskA2();               break;
    /* ... one case for every task number in the table ... */
    default:
        printf("no task %u\r\n", current);
        while (task == current) { }
        break;
}
/* switch off LD2 and all the RGB LEDs here */

/* a task with an end */
void taskA3(void)
{
    /* ... the work of A.3 ... */
    printf("=== task 13 done ===\r\n");
    while (task == 13) { }                   /* wait for another choice */
}

/* a task that runs until another one is chosen */
void taskB2(void)
{
    while (task == 22)
    {
        /* ... one step of B.2 ... */
    }
}
\end{lstlisting}

\paragraph{Printing the results: the line formats are MANDATORY.}
Every result is printed to PuTTY. A result line starts with the tag of its item (\texttt{A1:}, \texttt{B2:}, and so
on), followed by the fields exactly as shown in each item, separated by single spaces, and ends with
\texttt{\textbackslash r\textbackslash n}. Write numbers in decimal, unless specifically required otherwise. Write hex as
\texttt{0x} with capital letters and all the digits of the type (\texttt{0x0A}, \texttt{0x00FF}), and binary as
\texttt{0b} with all the bits of the type and no separators (\texttt{0b00001010}). You may print other lines as well,
as long as they do not start with a tag.

\paragraph{Part A: Variable types and range, signed and unsigned, wrap-around.}
\begin{enumerate}[label=A.\arabic*, leftmargin=2.2em]
  \item Increment a \texttt{uint8\_t}, an \texttt{int8\_t} and a \texttt{uint16\_t} past their limits. Start them at
        250, 120 and 65530. Print the start values, then add 1 to each of the three every 500\,ms, and print a line
        after each step; stop after 12 steps (13 lines in all). Each line:\\
        {\footnotesize\texttt{A1: u8=250 0xFA 0b11111010 i8=120 0x78 0b01111000 u16=65530 0xFFFA 0b1111111111111010}}\\
        The hex and binary fields show the bits stored in the variable: 8 bits for \texttt{u8} and \texttt{i8}, 16
        for \texttt{u16}.
        \textbf{Note:} the C library used with STM32CubeIDE supports the standard format specifiers, such as
        \texttt{\%d}, \texttt{\%u}, \texttt{\%x} and \texttt{\%o}, but it has no standard \texttt{\%b} specifier for
        binary output. You may use this function:
\begin{lstlisting}
/* print "0b" and the nBits lowest bits of value, the highest bit first */
void printBinary(uint32_t value, uint8_t nBits)
{
    printf("0b");
    for (int8_t i = (int8_t)(nBits - 1); i >= 0; i--)
    {
        putchar(((value >> i) & 1u) ? '1' : '0');
    }
}
\end{lstlisting}
        In your report, describe what happens when a variable passes its limit, and explain why.
  \item Explain how to read a hex number as a decimal value, and the difference between the signed and the unsigned
        cases. Show examples for \texttt{0x7F} (\texttt{uint8\_t} and \texttt{int8\_t}), \texttt{0xF0}
        (\texttt{uint8\_t} and \texttt{int8\_t}) and \texttt{0xFFF6} (\texttt{uint16\_t} and \texttt{int16\_t}).
        In your code, assign each value in its hex form to variables of both types, and print six lines, in the order
        above, for example:\\
        \texttt{A2: hex=0x7F uint8\_t dec=127 bin=0b01111111 raw=0x7F}\\
        \texttt{hex} and \texttt{bin} show the bits stored in the variable, as in A.1. \texttt{raw} is the variable
        printed with \texttt{0x\%X} as it is, without a cast. Explain what you see in \texttt{raw} when the value is
        negative.
  \item Integer division and casting. Two students took the MP course. One attended the classes and got 97; the other
        got 58. Store each grade in an unsigned integer variable, then compute their average: first in a way that
        gives a wrong result because of integer arithmetic, then in a way that gives the correct result. Show both in
        your code, print them as \texttt{A3: wrong=77 right=77.5}, and explain the difference in your report.
        \textbf{Hint:} by default, \texttt{printf} in STM32CubeIDE does not print \texttt{float} values
        (\texttt{\%f}). Either enable it in the project properties (\emph{C/C++ Build $\to$ Settings $\to$ Tool Settings $\to$ MCU Settings $\to$
        Use float with printf from newlib-nano}), or print the whole part and the tenths as two integers.
  % \item A brightness value that wraps around when it is increased past its maximum, then fixed with saturation.
\end{enumerate}

\paragraph{Part B: Bit operations and shifting.}
\begin{enumerate}[label=B.\arabic*, leftmargin=2.2em]
  \item Write the four bit operations as functions (not macros), using bitwise operators. Each takes a value and a bit
        number, and returns the result: \texttt{bitSet}, \texttt{bitClear} and \texttt{bitToggle} return the modified
        value, and \texttt{bitTest} returns 0 or 1. For example: \texttt{GPIOA->ODR = bitSet(GPIOA->ODR, 5);}\\
        Use them to control the Nucleo's green LED (LD2, bit~5 of \texttt{GPIOA->ODR}) directly, without the HAL GPIO
        functions. Run this sequence on LD2: clear the bit (LED off); wait 1\,s, set it (LED on); wait 1\,s, clear it
        (LED off); wait 1\,s, toggle it. After each step, read the bit back with \texttt{bitTest} and print it:\\
        \texttt{B1: start LD2=0}, \texttt{B1: set LD2=1}, \texttt{B1: clear LD2=0}, \texttt{B1: toggle LD2=1}\\
        Finally, show the last result on LED~0 of the IO board (lit if 1, off if 0), and print \texttt{B1: LED0=1}
        (or \texttt{=0}).
  \item Moving a single lit LED with bit operations. Keep the state of the 8 RGB LEDs in one \texttt{uint8\_t}
        variable, in which bit $n$ stands for LED $n$ (1 = lit). Light one LED at a time, with 1\,s between steps:
        LED~0, then LED~1, LED~2, and so on. After LED~7, return to LED~0, and repeat forever. At every step, print
        the variable that is shown on the LEDs: \texttt{B2: 0b00000001}, then \texttt{B2: 0b00000010}, and so on.
  \item A ``walking'' pair of LEDs. Repeat B.2, but with two adjacent LEDs lit: LEDs 0 and 1, then 1 and 2, and so
        on; after LEDs 6 and 7 come LEDs 7 and 0, then 0 and 1 again. Print \texttt{B3: 0b00000011}, and so on.
\end{enumerate}
\smallskip\noindent Rules for B.2 and B.3: the variable may change only through bit operations (shifts, OR, AND).
Choosing the pattern with \texttt{if}/\texttt{switch} chains, counters mapped to LEDs, or tables of precomputed
patterns is not accepted. Light the LEDs from the variable by testing its bits. In your report, explain how your code
moves the pattern past bit~7 without losing it.

\paragraph{Part C: Input triggering.}
\begin{enumerate}[label=C.\arabic*, leftmargin=2.2em]
  \item Read the raw button byte with \texttt{readButtonsRaw()}. Using bit operations, turn it into a value in which
        bit $n$ is 1 while button $n$ is held: invert the active-low bits, then clear bits 4 to 7 with a mask. Count
        how many buttons are held (0 to 4) by testing each bit. Print a line when the task starts and whenever the
        count changes:
        \texttt{C1: raw=0b00001110 held=0b00000001 count=1}
\end{enumerate}
In C.2 to C.5, count how many times button~0 of the IO board is pressed, in four versions. The count is done in
rounds, and \textbf{button~1 ends a round}: when it is pressed, print the result of the round with the tag of the item,
for example \texttt{C3: count=21}, set the count back to 0, and start the next round. Print once per press of
button~1: it bounces too, so, for example, ignore it for 0.5\,s after printing. Print nothing else while counting: a
printed line takes milliseconds, and would slow the loop down. Unless a task says otherwise, the loop has no delay, so
the buttons are read as fast as possible. In each version press button~0 exactly 20 times (It is encouraged to repeate it more than once, for statistics stabilty) at a natural
speed, then button~1. The hints say roughly what to expect; your report explains why.
\begin{enumerate}[label=C.\arabic*, leftmargin=2.2em, start=2]
  \item Level-based counting: increase the counter on every pass of the main loop while button~0 is held. Also count
        the loop passes, and add their number per second, over the round, to the result line:
        \texttt{C2: count=4317 passes=9680}. \textbf{Expect} a count much larger than 20.
  \item Edge-based counting: increase the counter only when button~0 changes from released to pressed
        (\texttt{now \& \textasciitilde before}). \textbf{Expect} 20 or a little more.
  \item Debounced edge counting: accept a change of the button state only after the new state has been stable for
        20\,ms (use \texttt{HAL\_GetTick}). \textbf{Expect} exactly 20.
  \item Missing presses: add \texttt{HAL\_Delay(150)} at the end of the loop of C.4 (task 35). It stands for another
        task running on the microcontroller, during which the code cannot check the button. Press the button 20 times,
        as briefly as you can. Repeat with the edge-based version of C.3 and the same delay (task 36).
        \textbf{Expect} much less than 20 in both versions, and even fewer in the debounced one.
        \textbf{Hint:} here, press button~1 for quite a long time (about half a second) to end a round; a quick press
        can be missed for the same reason.
\end{enumerate}
In your report, put all the results of C.2 to C.5 in one table and explain the differences, using the duration of a
press and the time of one loop pass. Explain why presses are lost in C.5, and why the debounced version loses more of
them.

\noindent\textbf{Video:} \texttt{V\_C}, showing C.1 to C.5 as they run, with PuTTY visible: in C.1 press several
combinations of buttons, and in each of C.2 to C.5 record one complete round: 20 presses of button~0, then button~1
and its result line. One representative round per version is enough for the video.

\paragraph{Part D: LED blinking and timing.}
\begin{enumerate}[label=D.\arabic*, leftmargin=2.2em]
  \item Write a loop that toggles LD2, prints a status line of about 60 characters to PuTTY with \texttt{printf}, and
        then waits with \texttt{HAL\_Delay(500)}; stop after 200 toggles. The status line starts with
        \texttt{D1: toggle=<n>}, and you choose the rest. Before running it, calculate how long the 200 toggles should
        take; then run it and measure the total time with \texttt{HAL\_GetTick} (read it before the first toggle and
        after the last). Print the result as \texttt{D1: toggles=200 total=<ms>}. In your report, explain why the total
        is not exactly 200 $\times$ 500\,ms (hint: think about the UART).
  \item Blink LD2 at a rate set by a global variable, declared exactly as
        \texttt{volatile uint32\_t blinkMs = 500;} (the on time, which is also the off time, in ms). Read it again

\smallskip\noindent Powers of two:
\begin{center}
\begin{tabular}{l*{8}{c}}
\toprule
$n$   & 0 & 1 & 2 & 3 & 4 & 5 & 6 & 7 \\
$2^n$ & 1 & 2 & 4 & 8 & 16 & 32 & 64 & 128 \\
\bottomrule
\end{tabular}
\end{center}

\begin{enumerate}[label=\textbf{Q\arabic*.}, leftmargin=2.5em, itemsep=6pt]
  \item What is the value of \texttt{x} after this code?
\begin{lstlisting}
uint8_t x = 250;
x = x + 10;
\end{lstlisting}
  \begin{enumerate}[label=(\alph*)]
    \item 260
    \item 4 \correct
    \item 255
    \item $-6$
  \end{enumerate}
  \begin{solution}
  \textbf{Solution.} \texttt{x + 10} is computed as an \texttt{int}: 260. A \texttt{uint8\_t} holds 0 to 255, so only
  the 8 lowest bits are stored: $260 - 256 = 4$ (260 = \texttt{0b1\,0000\,0100}, the 9th bit is lost). An unsigned
  variable wraps around; it does not stop at 255 (c), and it is never negative (d).
  \end{solution}

  \item What does this code print?
\begin{lstlisting}
int8_t s = 0xF0;
printf("%d\r\n", s);
\end{lstlisting}
  \begin{enumerate}[label=(\alph*)]
    \item 240
    \item $-16$ \correct
    \item $-112$
    \item 15
  \end{enumerate}
  \begin{solution}
  \textbf{Solution.} The stored bits are \texttt{1111\,0000}. In an \texttt{int8\_t} the highest bit has the weight
  $-128$: $-128 + 64 + 32 + 16 = -16$ (or: $240 - 256 = -16$). 240 (a) is the value of the same bits in a
  \texttt{uint8\_t}. $-112$ (c) treats the highest bit as a minus sign in front of \texttt{111\,0000} (sign and
  magnitude), which is not how the STM32 stores negative numbers. 15 (d) is the inverted bits.
  \end{solution}

  \item What is the value of \texttt{m}?
\begin{lstlisting}
uint16_t a = 25, b = 30;
float m = (a + b) / 2;
\end{lstlisting}
  \begin{enumerate}[label=(\alph*)]
    \item 27.5
    \item 27.0 \correct
    \item 28.0
    \item 55.0
  \end{enumerate}
  \begin{solution}
  \textbf{Solution.} \texttt{a + b} and \texttt{2} are integers, so the division is an integer division: $55 / 2 = 27$,
  the fraction is thrown away (not rounded, so not 28). Only then is 27 converted to \texttt{float}. The type of the
  variable on the left does not change how the right side is computed. To get 27.5: \texttt{(a + b) / 2.0f}, or
  \texttt{(float)(a + b) / 2}.
  \end{solution}

  \item Which expression clears bit 4 of \texttt{x} and leaves all its other bits unchanged, for every value of
  \texttt{x}?
  \begin{enumerate}[label=(\alph*)]
    \item \texttt{x \& (1 <{}< 4)}
    \item \texttt{x | \textasciitilde(1 <{}< 4)}
    \item \texttt{x \& \textasciitilde(1 <{}< 4)} \correct
    \item \texttt{x \^{} (1 <{}< 4)}
  \end{enumerate}
  \begin{solution}
  \textbf{Solution.} \texttt{\textasciitilde(1 <{}< 4)} is a mask with all bits 1 except bit 4. AND with 1 keeps a
  bit, AND with 0 clears it, so (c) clears bit 4 only. (a) keeps bit 4 only and clears all the others (it tests the
  bit). (b) sets every bit except bit 4. (d) toggles bit 4: it clears it only when it was 1, and sets it when it was 0.
  \end{solution}

  \item The 8 LEDs are kept in \texttt{p}, bit $n$ for LED $n$. What is \texttt{p} after this code?
\begin{lstlisting}
uint8_t p = 0b10000001;
p = (p << 1) | (p >> 7);
\end{lstlisting}
  \begin{enumerate}[label=(\alph*)]
    \item \texttt{0b00000010}
    \item \texttt{0b00000011} \correct
    \item \texttt{0b10000010}
    \item \texttt{0b00000001}
  \end{enumerate}
  \begin{solution}
  \textbf{Solution.} \texttt{p <{}< 1} = \texttt{0b1\,0000\,0010} (computed as an \texttt{int}, so bit 7 moves to bit
  8). \texttt{p >{}> 7} = \texttt{0b0000\,0001}: the old bit 7 comes back as bit 0. The OR gives
  \texttt{0b1\,0000\,0011}, and storing it in the \texttt{uint8\_t} drops bit 8: \texttt{0b00000011}. This is a
  rotation by one place: both lit LEDs move up by one, and the LED that was at position 7 continues at position 0
  (as in A1, B.3). (a) is the shift alone, without the bit that wraps around.
  \end{solution}

  \item A program counts presses with level-based counting: on every pass of the main loop, the counter grows by 1 if
  the button is held. One pass of the loop takes 50\,\textmu s, and each press holds the button for about 120\,ms.
  After 20 presses, the counter is about:
  \begin{enumerate}[label=(\alph*)]
    \item 20
    \item 120
    \item 2\,400
    \item 48\,000 \correct
  \end{enumerate}
  \begin{solution}
  \textbf{Solution.} During one press the loop runs 120\,ms / 50\,\textmu s = 2\,400 times, and the
  counter grows on each of these passes. For 20 presses: $20 \times 2\,400 = 48\,000$. (c) is one press only. Counting
  a press once needs edge-based counting: count only when the state changes from released to pressed (A1, C.2 and C.3).
  \end{solution}

  \item An edge-based button counter reads the button once per pass, and each pass ends with
  \texttt{HAL\_Delay(150)} (the rest of the loop takes much less than 1\,ms). The button is pressed 20 times, at random
  moments, and each press lasts 60\,ms. The counter shows about:
  \begin{enumerate}[label=(\alph*)]
    \item 20
    \item 8 \correct
    \item 0
    \item 40
  \end{enumerate}
  \begin{solution}
  \textbf{Solution.} The button is read once every 150\,ms. A press is counted only if one of the reads falls inside
  the 60\,ms of the press. Since the presses come at random moments, the chance is $60 / 150 = 0.4$, so about
  $0.4 \times 20 = 8$ presses are counted, and the rest are missed. Not 0 (c), because some reads do fall inside a
  press. Not more than 20 (d): the bounces last a few ms, so reads 150\,ms apart cannot count one press twice. A press longer
  than 150\,ms would always be seen (A1, C.5).
  \end{solution}
\end{enumerate}

\paragraph{Open question: write the code.}
Write a function \texttt{void blinkAndCount(void)} that runs forever and does two things at the same time, with no
\texttt{HAL\_Delay} and no other waiting:
\begin{enumerate}[label=(\arabic*)]
  \item LD2 (bit 5 of \texttt{GPIOA->ODR}) toggles every 250\,ms. Toggle it with a bitwise operator, not with the HAL
        GPIO functions; time it with \texttt{HAL\_GetTick()}.
  \item It counts the presses of button~0 of the IO board, edge-based, and prints \texttt{count=<n>} each time the
        count grows. This part is given: copy it into your loop as it is.
\end{enumerate}
\begin{lstlisting}
/* (2) count the presses of button 0 */
uint8_t now = (~readButtonsRaw()) & 0x01;      /* 1 while held (active-low) */
if (now && !before)                            /* released -> pressed */
{
    count++;
    printf("count=%lu\r\n", count);
}
before = now;
\end{lstlisting}
Write the whole function: the variables it needs (also those that part (2) uses), the loop, part (1), and part (2) in
its place. Then explain in one sentence why the function must not use \texttt{HAL\_Delay}.
\answerspace{12cm}

\begin{solution}
\medskip\noindent\textbf{Solution.}
\begin{lstlisting}
void blinkAndCount(void)
{
    uint32_t lastToggle = HAL_GetTick();
    uint8_t before = 0;            /* button 0 was released */
    uint32_t count = 0;

    while (1)
    {
        /* (1) toggle LD2 every 250 ms, without waiting */
        if (HAL_GetTick() - lastToggle >= 250)
        {
            lastToggle += 250;
            GPIOA->ODR ^= (1u << 5);                   /* XOR toggles bit 5 only */
        }

        /* (2) count the presses of button 0 */
        uint8_t now = (~readButtonsRaw()) & 0x01;      /* 1 while held (active-low) */
        if (now && !before)                            /* released -> pressed */
        {
            count++;
            printf("count=%lu\r\n", count);
        }
        before = now;                                  /* remember for the next pass */
    }
}
\end{lstlisting}
\textbf{Why no \texttt{HAL\_Delay}:} while \texttt{HAL\_Delay} waits, the loop does not read the button, so a press
that starts and ends during the wait is missed (Q7), and the toggles are delayed by the time the rest of the loop takes.

\medskip\noindent\textbf{What to check when grading:}
\begin{itemize}
  \item The timing compares \texttt{HAL\_GetTick() - lastToggle} with 250 and moves \texttt{lastToggle} on.
        \texttt{lastToggle = HAL\_GetTick()} is accepted too (the period may grow by a fraction of a ms). The unsigned
        subtraction is right even when the tick counter wraps around.
  \item LD2 is toggled with XOR on bit 5 (\texttt{\^{}=}); reading the bit and writing it back with set or clear is
        accepted.
  \item The variables of part (2) are declared before the loop, with suitable types and start values:
        \texttt{before} (\texttt{uint8\_t}, 0) and \texttt{count} (\texttt{uint32\_t}, 0, to match \texttt{\%lu}).
        Declaring them inside the loop resets them on every pass, and the count never grows past 1.
  \item Part (2) is inside the loop, once per pass, and part (1) does not wait: no \texttt{HAL\_Delay}, no
        \texttt{while} that waits for the time to pass.
\end{itemize}
\end{solution}

\paragraph{Part B: Obstacle course.}
The cart drives forward along a straight line under the speed control of Part~A. When it detects an obstacle ahead, it
